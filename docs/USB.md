Version: 2.0.0

Status: Draft

# 1. Purpose

Настоящий документ определяет архитектуру USB-подсистемы проекта **KeyKeeper2**.

Документ описывает:

- работу устройства как USB HID Keyboard;
- архитектуру USBService;
- последовательности ввода данных;
- взаимодействие с другими компонентами проекта;
- требования безопасности.

USB.md является дополнением к документам:

- ARCHITECTURE.md
- SOFTWARE.md
- SECURITY.md
- EVENTS.md
- GUI.md

---

# 2. USB Overview

Устройство определяется компьютером как стандартная USB HID-клавиатура.

Дополнительные драйверы не требуются.

USB-подсистема предназначена для быстрого и безопасного ввода данных пользователя.

---

## Supported Features

Поддерживаются следующие операции:

- Print URL;
- Print Username;
- Print Password;
- Print OTP;
- пользовательские последовательности ввода.

---

## Non-Goals

USB-подсистема не отвечает за:

- хранение данных;
- проверку PIN;
- отображение GUI;
- работу с файловой системой.

Эти функции реализуются другими компонентами проекта.

---

# 3. Design Principles

USB-подсистема строится на следующих принципах:

- Single Responsibility;
- Security First;
- Component Isolation;
- Event-Driven Architecture;
- Documentation First.

---

## Separation of Responsibilities

USB отвечает только за передачу данных компьютеру.

Подсистема не принимает решений о доступе к защищённой информации.

Все проверки безопасности выполняются через **SecurityService**.

---

# 4. USB Architecture

USB-подсистема представляет собой отдельный компонент проекта.

```text
components/

usb/
```

Основная схема взаимодействия:

```text
GUI

↓

EventBus

↓

USBService

↓

TinyUSB

↓

USB HID
```

GUI не взаимодействует с TinyUSB напрямую.

---

## Component Responsibilities

USBService отвечает за:

- инициализацию USB;
- управление состоянием подключения;
- передачу HID-отчётов;
- обработку пользовательских последовательностей ввода;
- публикацию событий через EventBus.

---

# 5. USBService

USBService является единственной публичной точкой доступа к USB-подсистеме.

Все остальные компоненты работают только через его API.

---

## Responsibilities

USBService отвечает за:

- запуск USB;
- остановку USB;
- определение состояния подключения;
- отправку HID-отчётов;
- выполнение операций печати.

---

## Public Operations

Основные операции:

- Initialize();
- Start();
- Stop();
- IsConnected();
- PrintUrl();
- PrintUsername();
- PrintPassword();
- PrintOtp();
- PrintSequence().

---

## Connection State

USBService должен отслеживать текущее состояние USB-соединения.

Поддерживаются состояния:

- Disconnected;
- Connected;
- Suspended.

Изменение состояния сопровождается публикацией соответствующих событий.

---

# 6. HID Keyboard

Устройство работает как стандартная USB HID-клавиатура.

Используется библиотека **TinyUSB**, входящая в состав ESP-IDF.

---

## Keyboard Layout

По умолчанию используется стандартная раскладка HID.

При необходимости допускается поддержка различных раскладок клавиатуры через настройки проекта.

---

## Character Transmission

Передача символов выполняется последовательно.

Каждое нажатие клавиши должно сопровождаться её последующим отпусканием.

---

## Timing

USBService должен обеспечивать корректные интервалы между отправкой HID-отчётов.

Параметры задержек должны быть настраиваемыми через SettingsService.

---

# 7. Print Operations

USBService поддерживает несколько стандартных операций передачи данных.

---

## Print URL

Передаёт URL выбранной записи.

Перед началом операции выполняется проверка доступа через SecurityService.

---

## Print Username

Передаёт имя пользователя выбранной записи.

Доступ разрешается только после успешной проверки безопасности.

---

## Print Password

Передаёт пароль выбранной записи.

Это защищённая операция.

Перед выполнением обязательно подтверждение через SecurityService.

---

## Print OTP

Передаёт одноразовый код (OTP), сгенерированный VaultService.

USBService не вычисляет OTP самостоятельно и не хранит секреты — он получает готовое значение для передачи после успешной проверки безопасности.

---

# 8. Quick Screen Integration

USB-подсистема поддерживает выполнение быстрых операций из **Quick Screen**.

Quick Screen предназначен для быстрого доступа к наиболее востребованным функциям устройства.

---

## Supported Actions

Поддерживаются следующие действия:

```text
Short BACK → Unlock

Long BACK → Print Password

Short OK → Print URL
```

При необходимости набор быстрых действий может быть расширен через настройки проекта.

---

## Workflow

Типичный сценарий выполнения команды:

```text
User Action

↓

GUI

↓

EventBus

↓

SecurityService

↓

VaultService

↓

USBService

↓

USB HID
```

Каждый компонент выполняет только собственную область ответственности.

---

## User Experience

Во время передачи данных GUI должен отображать текущее состояние операции.

Например:

- Sending...
- Completed
- Failed

Сообщения не должны содержать конфиденциальную информацию.

---

# 9. Security Integration

Все операции передачи конфиденциальных данных относятся к защищённым операциям.

---

## Security Rules

USBService не выполняет:

- проверку PIN;
- проверку сессии;
- управление разрешениями.

Все проверки выполняются через **SecurityService**.

---

## Protected Operations

К защищённым относятся:

- Print Password;
- Print Username;
- Print OTP;
- пользовательские последовательности, содержащие конфиденциальные данные.

---

## Authorization Flow

Типичная последовательность:

```text
GUI

↓

SecurityService

↓

VaultService

↓

USBService
```

Если доступ запрещён, USBService не получает данные для передачи.

---

## Data Lifetime

Конфиденциальные данные должны существовать в памяти только минимально необходимое время.

После завершения передачи временные буферы должны быть очищены.

---

# 10. EventBus Integration

USB-подсистема взаимодействует с остальными компонентами исключительно через **EventBus**.

---

## Published Events

USBService публикует события:

- UsbConnected;
- UsbDisconnected;
- UrlPrinted;
- UsernamePrinted;
- PasswordPrinted;
- OtpPrinted;
- UsbError.

---

## Subscribed Events

USBService может подписываться на события:

- SessionUnlocked;
- SessionLocked;
- PrintRequested;
- SettingsChanged;
- ShutdownRequested.

---

## Event Processing

Все события должны обрабатываться асинхронно.

USBService не должен блокировать EventBus во время передачи HID-отчётов.

---

# 11. Error Handling

Все ошибки USB-подсистемы должны корректно обрабатываться.

---

## Error Categories

Основные категории ошибок:

- USB Not Connected;
- HID Transmission Failed;
- Permission Denied;
- Invalid Request;
- Device Busy;
- Internal Error.

---

## User Notification

GUI отображает пользователю только необходимую информацию.

Например:

- USB disconnected
- Permission denied
- Transmission failed

Технические детали ошибки должны оставаться в журнале.

---

## Recovery

После устранения причины ошибки USBService должен автоматически возвращаться в рабочее состояние без перезагрузки устройства.

---

# 12. Performance

USB-подсистема должна обеспечивать быстрый и стабильный ввод данных.

---

## Requirements

При реализации необходимо:

- минимизировать задержки между HID-отчётами;
- избегать блокирующих операций;
- использовать внутренние буферы только при необходимости;
- выполнять передачу последовательно.

---

## Responsiveness

Передача данных не должна ухудшать работу GUI.

Пользовательский интерфейс должен оставаться полностью отзывчивым.

---

# 13. Future Extensions

Архитектура USB-подсистемы должна предусматривать возможность дальнейшего расширения.

Планируемые направления развития:

- пользовательские HID-макросы;
- настраиваемые последовательности ввода;
- поддержка нескольких профилей;
- автоматическая задержка между полями;
- дополнительные типы HID-устройств;
- расширенные параметры клавиатурной раскладки.

Все новые функции должны быть реализованы без изменения публичного API USBService.

---

# 14. Summary

Подсистема **USB** обеспечивает безопасную передачу пользовательских данных на компьютер, работая как стандартная **USB HID Keyboard**.

Архитектура построена вокруг компонента **USBService**, который отвечает исключительно за передачу HID-отчётов и не содержит логики безопасности, хранения данных или пользовательского интерфейса.

Все операции выполняются во взаимодействии с **SecurityService**, **VaultService** и **EventBus**, что обеспечивает чёткое разделение ответственности, соответствие архитектуре проекта и возможность дальнейшего расширения без нарушения существующего API.
