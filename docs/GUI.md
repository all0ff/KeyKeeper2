# GUI.md

# KeyKeeper2 GUI Design Specification

Version: 2.0.0

Status: Draft

---

# 1. Purpose

Настоящий документ определяет требования к графическому интерфейсу пользователя (GUI) проекта **KeyKeeper2**.

Документ описывает:

- структуру интерфейса;
- навигацию;
- поведение экранов;
- элементы управления;
- визуальный стиль;
- взаимодействие GUI с сервисами проекта.

GUI.md является дополнением к следующим документам:

- REQUIREMENTS.md
- ARCHITECTURE.md
- SOFTWARE.md
- SECURITY.md

---

# 2. GUI Philosophy

Интерфейс должен быть максимально простым, быстрым и понятным.

Основные принципы:

- One Hand Operation
- Minimal Clicks
- Clear Navigation
- Consistent Design
- Dark Theme First
- Fast Access
- Documentation First

Каждое действие пользователя должно требовать минимального количества операций.

---

# 3. GUI Architecture

GUI является отдельным компонентом проекта.

```text
components/

gui/
```

GUI отвечает только за отображение информации и обработку действий пользователя.

Вся бизнес-логика находится в сервисном слое.

---

## 3.1 GUI Responsibilities

GUI отвечает за:

- отображение экранов;
- обработку энкодера;
- обработку кнопок;
- отображение диалогов;
- отображение уведомлений;
- отображение состояния устройства;
- анимации.

GUI не отвечает за:

- хранение данных;
- проверку PIN;
- криптографию;
- работу с USB;
- работу с Wi-Fi;
- работу с файловой системой.

---

## 3.2 GUI Interaction

GUI взаимодействует только с сервисами.

```text
Screen

↓

ScreenManager

↓

Presenter

↓

Service

↓

EventBus
```

Прямое обращение GUI к другим компонентам запрещено.

---

# 4. Screen Manager

ScreenManager управляет жизненным циклом экранов.

Он отвечает за:

- создание экранов;
- уничтожение экранов;
- переключение экранов;
- возврат назад;
- анимацию переходов.

---

## Screen Lifecycle

Каждый экран проходит следующие состояния:

```text
Create

↓

Initialize

↓

Show

↓

Active

↓

Hide

↓

Destroy
```

Экран не должен самостоятельно создавать другие экраны.

---

# 5. Input Model

Основным устройством управления является энкодер.

Поддерживаются следующие действия:

- Rotate Left
- Rotate Right
- Short Press
- Long Press

При необходимости могут использоваться дополнительные аппаратные кнопки, но интерфейс не должен зависеть от их наличия.

---

## Navigation Rules

Во всём интерфейсе используются единые правила:

- вращение — перемещение по спискам;
- короткое нажатие — выбор элемента;
- длинное нажатие — дополнительное действие или контекстное меню (если предусмотрено).

Поведение одинаковых элементов должно быть одинаковым на всех экранах.

---

# 6. Screen Structure

Каждый экран имеет одинаковую структуру.

```text
┌──────────────────────────────┐
│ Header                       │
├──────────────────────────────┤
│                              │
│ Content                      │
│                              │
├──────────────────────────────┤
│ Footer / Hint                │
└──────────────────────────────┘
```

---

## Header

Header отображает:

- заголовок;
- текущий раздел;
- индикаторы состояния (при необходимости).

---

## Content

Основная область экрана.

Здесь располагаются:

- списки;
- карточки;
- формы;
- диалоги;
- сообщения;
- меню.

---

## Footer

Footer отображает контекстные подсказки для пользователя.

Например:

```text
BACK • Unlock

OK • Print URL
```

или

```text
OK • Select

BACK • Return
```

Подсказки должны соответствовать текущему экрану.

---

# 7. Main Screen

После включения устройства отображается стартовый экран (Quick Screen).

Это главный экран устройства.

---

## Purpose

Quick Screen обеспечивает максимально быстрый доступ к наиболее востребованным функциям без перехода в основное меню.

---

## Layout

На экране отображаются:

- логотип проекта;
- название устройства;
- текущее состояние блокировки;
- краткие подсказки по действиям пользователя.

Пример структуры:

```text
┌──────────────────────────────┐
│          KeyKeeper2          │
│                              │
│         🔒 Locked            │
│                              │
│                              │
├──────────────────────────────┤
│ BACK Unlock                  │
│ OK   Print URL               │
└──────────────────────────────┘
```

(В прошивке используется собственный монохромный набор пиктограмм, а не Emoji.)

---

## Quick Actions

Для стартового экрана определены следующие действия:

```text
Short BACK → Unlock

Long BACK → Print Password

Short OK → Print URL
```

---

## Unlock

Команда **Unlock** открывает экран ввода PIN.

После успешной проверки через **SecurityService** пользователь получает доступ к полной функциональности устройства.

---

## Print URL

Команда **Print URL** отправляет через USB URL, связанный с паролем по умолчанию.

Если URL отсутствует, операция завершается без выполнения действий.

---

## Print Password

Команда **Print Password** отправляет через USB пароль по умолчанию.

Если пароль не задан или поле пустое, операция не выполняется.

Перед передачей защищённых данных выполняется проверка через **SecurityService**.

---

# 8. Lock Screen

Экран блокировки отображается:

- после включения устройства;
- после Auto Lock;
- после ручной блокировки.

Экран содержит:

- индикатор блокировки;
- поле ввода PIN;
- сообщения об ошибках;
- информацию о количестве оставшихся попыток (если эта функция включена).

После успешного ввода PIN выполняется переход к главному меню.

---

# 9. Main Menu

После разблокировки пользователь попадает в главное меню.

Основные разделы:

- Vault
- Favorites
- Categories
- Search
- Settings
- Backup
- System

Главное меню должно быть компактным и легко управляться энкодером.

---

# 10. Vault Screen

Экран Vault является основным рабочим экраном приложения.

Он отображает список сохранённых учётных записей.

Для каждой записи могут отображаться:

- название;
- категория;
- URL (при необходимости);
- индикатор OTP;
- признак «Избранное».

Выбор записи открывает экран её просмотра или редактирования.

---

# 11. Account Screen

Экран отображает полную информацию о выбранной учётной записи.

---

## Displayed Information

Могут отображаться следующие поля:

- Name
- URL
- Username
- Password
- OTP
- Notes
- Category
- Favorite

Пустые поля не отображаются.

---

## Available Actions

Пользователь может выполнить:

- Print URL
- Print Username
- Print Password
- Print OTP
- Edit
- Delete

Все защищённые операции выполняются только после проверки SecurityService.

---

# 12. Edit Screen

Экран предназначен для создания и редактирования учётных записей.

---

## Editable Fields

Поддерживаются следующие поля:

- Name
- URL
- Username
- Password
- OTP Secret
- Notes
- Category
- Favorite

---

## Validation

Перед сохранением выполняется проверка данных.

Минимальные требования:

- Name не может быть пустым;
- OTP должен иметь корректный формат;
- длина строк не должна превышать допустимых ограничений.

---

## Save

После успешной проверки данные передаются в VaultService.

GUI не сохраняет данные самостоятельно.

---

# 13. Search Screen

Экран предназначен для быстрого поиска учётных записей.

---

## Search Features

Поддерживаются:

- поиск по названию;
- поиск по URL;
- поиск по логину;
- фильтрация по категории;
- отображение избранных записей.

---

## Search Behavior

Результаты поиска обновляются динамически.

Пустой запрос отображает полный список записей.

---

# 14. Settings Screens

Все настройки разделены на независимые разделы.

---

## General Settings

Поддерживаются:

- Language
- Theme
- Display Brightness
- Screen Timeout
- Auto Lock

---

## USB Settings

Настраиваются:

- Password Shortcut;
- Print Delays;
- Print Sequence.

---

## Security Settings

Настраиваются:

- Change PIN;
- Auto Lock Timeout;
- Security Options.

Все изменения выполняются через SecurityService.

---

## System Settings

Отображаются:

- версия прошивки;
- версия базы данных;
- информация об устройстве;
- объём свободной памяти;
- информация о накопителе.

---

# 15. Backup Screens

Экран резервного копирования предназначен для управления пользовательскими данными.

---

## Available Actions

Поддерживаются:

- Create Backup;
- Restore Backup;
- Export Vault;
- Import Vault.

Перед выполнением защищённых операций выполняется проверка SecurityService.

---

## Progress

Длительные операции должны отображать:

- индикатор выполнения;
- текущий этап;
- возможность отмены (если поддерживается).

GUI не должен блокироваться во время выполнения длительных операций.

---

# 16. Dialogs

Все диалоговые окна используют единый стиль оформления.

---

## Supported Dialogs

Используются следующие типы:

- Information;
- Confirmation;
- Warning;
- Error;
- Progress.

---

## Confirmation Dialog

Используется перед выполнением необратимых действий.

Например:

- Delete Account;
- Restore Backup;
- Factory Reset.

---

## Error Dialog

Должен содержать:

- понятное описание ошибки;
- возможное решение (если применимо);
- кнопку закрытия.

---

# 17. Notifications

GUI поддерживает кратковременные уведомления.

---

## Notification Types

Используются:

- Success;
- Information;
- Warning;
- Error.

---

## Duration

Время отображения уведомления должно быть ограничено.

Повторяющиеся уведомления не должны перекрывать друг друга.

---

# 18. Visual Design

Проект использует единый визуальный стиль.

---

## Color Palette

Основной режим работы:

- Dark Theme.

Используются:

- основной цвет;
- акцентный цвет;
- цвет предупреждения;
- цвет ошибки;
- цвет успешной операции.

Все цвета определяются ThemeService.

---

## Typography

Используется единый набор шрифтов.

Правила:

- одинаковые размеры для однотипных элементов;
- единые интервалы;
- хорошая читаемость.

---

## Icons

Проект использует собственный набор монохромных SVG-пиктограмм.

Поддерживаются базовые пиктограммы:

- Vault;
- Folder;
- Favorite;
- Search;
- Settings;
- USB;
- Wi-Fi;
- Backup;
- Restore;
- Import;
- Export;
- Lock;
- Unlock;
- Password;
- User;
- URL;
- Globe;
- OTP;
- Edit;
- Delete;
- Save;
- Cancel;
- Warning;
- Error;
- Success;
- Info;
- Language;
- Theme;
- Brightness;
- SD Card;
- Flash;
- About.

Все пиктограммы должны иметь единый стиль, одинаковую толщину линий и масштаб.

Использование сторонних библиотек иконок не допускается.

---

# 19. GUI Performance

Интерфейс должен оставаться отзывчивым при любых операциях.

---

## Requirements

GUI не должен:

- выполнять длительные операции;
- обращаться напрямую к файловой системе;
- ожидать завершения сетевых запросов;
- блокировать цикл обработки LVGL.

Все длительные операции выполняются в фоновых задачах.

---

## Animation

Анимации должны быть:

- плавными;
- короткими;
- одинаковыми во всём интерфейсе.

Избыточные визуальные эффекты не используются.

---

# 20. Summary

GUI проекта **KeyKeeper2** построен на принципах **One Hand Operation**, **Minimal Clicks**, **Consistent Design** и **Documentation First**.

Интерфейс полностью отделён от бизнес-логики и взаимодействует с системой только через сервисный слой и EventBus.

Все операции, связанные с безопасностью, проходят через **SecurityService**, а работа с данными осуществляется исключительно через **VaultService** и **StorageService**.

Использование единой системы экранов, собственного набора монохромных SVG-пиктограмм, общей темы оформления и унифицированных элементов управления обеспечивает целостный внешний вид, простоту сопровождения и возможность дальнейшего развития проекта без изменения базовой архитектуры.
