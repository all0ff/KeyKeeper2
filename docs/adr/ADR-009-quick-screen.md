# ADR-009 — Quick Screen

**Status:** Accepted

**Date:** YYYY-MM-DD

**Version:** 2.0

---

# Context

Проект **KeyKeeper2** предназначен для максимально быстрого доступа к наиболее востребованным пользовательским операциям.

Большинство действий пользователя сводится к нескольким типовым сценариям:

* разблокировка устройства;
* передача URL;
* передача имени пользователя;
* передача пароля;
* получение OTP.

Полная навигация по меню обеспечивает доступ ко всем функциям устройства, однако выполнение повседневных операций через многоуровневое меню увеличивает количество действий пользователя и ухудшает удобство использования.

Для ускорения работы устройства принято решение выделить отдельный экран быстрого доступа — **Quick Screen**.

---

# Decision

В архитектуре проекта используется специализированный экран **Quick Screen**, обеспечивающий выполнение наиболее часто используемых операций с минимальным количеством действий пользователя.

Quick Screen является частью GUI, но не содержит бизнес-логики.

Все действия выполняются через соответствующие сервисы приложения.

---

# Architecture

Quick Screen располагается в составе GUI и взаимодействует с системой через EventBus.

Типовая схема обработки команды:

```text id="p9v4cm"
User

↓

Quick Screen

↓

EventBus

↓

SecurityService

↓

VaultService

↓

USBService
```

Экран не обращается напрямую к компонентам хранения данных или безопасности.

---

# Responsibilities

Quick Screen отвечает исключительно за:

* отображение быстрых действий;
* обработку пользовательского ввода;
* отправку команд через EventBus;
* отображение результата выполнения операции.

Quick Screen не принимает решений о безопасности и не работает напрямую с пользовательскими данными.

---

# Supported Operations

Quick Screen предоставляет быстрый доступ к наиболее востребованным действиям.

Типичный набор операций:

* Unlock;
* Print URL;
* Print Username;
* Print Password;
* Print OTP.

Конкретный состав операций определяется настройками проекта и может быть расширен в будущем.

---

# Security Integration

Все операции Quick Screen проходят обязательную проверку через SecurityService.

Quick Screen не знает:

* введён ли корректный PIN;
* активна ли пользовательская сессия;
* разрешено ли выполнение операции.

После отказа SecurityService выполнение команды прекращается.

---

# EventBus Integration

Quick Screen взаимодействует с системой исключительно через события.

Основные публикуемые события:

* QuickActionRequested;
* QuickActionCancelled.

Основные получаемые события:

* SessionUnlocked;
* SessionLocked;
* PasswordPrinted;
* UrlPrinted;
* UsernamePrinted;
* OtpPrinted;
* OperationFailed.

---

# User Experience

Quick Screen должен обеспечивать:

* минимальное количество действий пользователя;
* быстрое выполнение операций;
* понятную навигацию;
* мгновенную визуальную обратную связь.

Все действия должны сопровождаться индикацией текущего состояния:

* выполнение;
* успешно;
* ошибка.

Сообщения не должны раскрывать конфиденциальную информацию.

---

# Rationale

Использование Quick Screen обеспечивает:

* сокращение количества действий пользователя;
* ускорение доступа к наиболее востребованным функциям;
* уменьшение глубины навигации;
* более удобную работу устройства в повседневном использовании.

Такой подход позволяет сохранить полноценное меню для всех функций и одновременно предоставить максимально быстрый доступ к основным операциям.

---

# Consequences

После принятия данного решения:

* Quick Screen становится основной точкой быстрого доступа к функциям устройства;
* все действия Quick Screen выполняются через сервисный слой;
* запрещается размещать бизнес-логику внутри Quick Screen;
* новые быстрые операции должны интегрироваться через EventBus и соответствующие сервисы.

---

# Alternatives Considered

## Выполнение всех операций через основное меню

Преимущества:

* более простая структура GUI;
* отсутствие отдельного экрана.

Недостатки:

* увеличение количества действий пользователя;
* снижение скорости выполнения повседневных операций;
* ухудшение удобства использования.

Данный вариант был отклонён.

---

## Размещение быстрых функций непосредственно на главном экране

Рассматривалась возможность интеграции быстрых операций в главный экран.

Недостатки:

* перегруженный интерфейс;
* сложность масштабирования;
* ухудшение читаемости GUI.

Данный вариант также был отклонён.

# Summary

Проект **KeyKeeper2** использует специализированный экран **Quick Screen** для выполнения наиболее востребованных пользовательских операций.

Quick Screen является частью графического интерфейса, не содержит бизнес-логики и взаимодействует с системой через EventBus и сервисный слой. Такое решение обеспечивает высокую скорость работы, улучшает пользовательский опыт и полностью соответствует компонентной архитектуре проекта.
