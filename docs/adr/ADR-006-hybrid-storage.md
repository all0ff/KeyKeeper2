# ADR-006 — Hybrid Storage

**Status:** Accepted

**Date:** YYYY-MM-DD

**Version:** 2.0

---

# Context

Проект **KeyKeeper2** использует два типа физических носителей данных:

* внутреннюю Flash-память (LittleFS);
* карту памяти microSD.

Каждый носитель обладает собственными преимуществами и ограничениями. Внутренняя память обеспечивает постоянную доступность и высокую скорость работы, тогда как microSD удобна для резервного копирования, импорта, экспорта и переноса данных между устройствами.

Для обеспечения надёжности и удобства эксплуатации принято решение использовать гибридную модель хранения данных.

---

# Decision

В проекте используется **Hybrid Storage Architecture**, при которой каждый носитель применяется строго по своему назначению.

Основная рабочая база данных хранится во внутренней памяти устройства (LittleFS), а карта microSD используется только для дополнительных операций.

---

# Storage Layout

Общая схема хранения данных:

```text
                 Storage

                    │

        ┌───────────┴───────────┐

        │                       │

    LittleFS                 microSD

        │                       │

  vault.db                Backup Files

  settings.json           Import Files

  system.log              Export Files

                           User Files
```

---

# Responsibilities

## LittleFS

Является основным рабочим хранилищем.

Используется для:

* базы данных `vault.db`;
* пользовательских настроек;
* системных конфигураций;
* временных служебных файлов.

LittleFS всегда доступна и не зависит от наличия карты памяти.

---

## microSD

Используется как дополнительное внешнее хранилище.

Предназначена для:

* резервного копирования;
* восстановления данных;
* импорта;
* экспорта;
* хранения пользовательских файлов.

Работа устройства не должна зависеть от наличия microSD.

---

# Storage Workflow

Типичная схема работы:

```text
GUI

↓

VaultService

↓

StorageService

↓

StorageProvider

↓

LittleFS
```

При выполнении операций резервного копирования:

```text
VaultService

↓

StorageService

↓

StorageProvider

↓

microSD
```

---

# Rationale

Использование гибридной модели хранения обеспечивает:

* высокую скорость работы основной базы данных;
* независимость устройства от карты памяти;
* простое резервное копирование;
* удобный перенос данных;
* снижение риска потери информации.

Такой подход позволяет объединить преимущества внутренней памяти и съёмного носителя без усложнения архитектуры приложения.

---

# Consequences

После принятия данного решения:

* рабочая база данных всегда размещается во внутренней Flash-памяти;
* отсутствие microSD не влияет на основную функциональность устройства;
* все операции резервного копирования и восстановления выполняются через StorageService;
* прямой доступ компонентов к физическим носителям запрещён.

---

# Alternatives Considered

## Хранение всех данных только в LittleFS

Преимущества:

* простая архитектура;
* отсутствие зависимости от карты памяти.

Недостатки:

* неудобное резервное копирование;
* сложность переноса данных между устройствами.

Данный вариант был отклонён.

---

## Хранение основной базы данных на microSD

Преимущества:

* большой объём памяти;
* лёгкая замена носителя.

Недостатки:

* зависимость работы устройства от установленной карты памяти;
* снижение надёжности при извлечении карты;
* увеличение времени доступа к данным.

Данный вариант также был отклонён.

# Summary

Проект **KeyKeeper2** использует **Hybrid Storage Architecture**, в которой внутренняя память LittleFS является основным рабочим хранилищем, а microSD применяется для резервного копирования, импорта, экспорта и переноса данных.

Такое решение обеспечивает высокую надёжность, независимость от внешних носителей, удобство эксплуатации и полностью соответствует компонентной архитектуре проекта.
