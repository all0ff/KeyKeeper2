# ADR-010 — Icon System

**Status:** Accepted

**Date:** YYYY-MM-DD

**Version:** 2.0

---

# Context

Графический интерфейс **KeyKeeper2** активно использует визуальные элементы для отображения состояния устройства, навигации и пользовательских действий.

Использование отдельных изображений для каждой иконки приводит к:

* увеличению объёма прошивки;
* усложнению масштабирования;
* необходимости хранения большого количества графических ресурсов;
* усложнению поддержки нескольких тем оформления.

Для обеспечения единообразного интерфейса необходимо использовать единую систему отображения иконок.

---

# Decision

В проекте используется единая **Icon Font System**, основанная на шрифте с векторными пиктограммами.

Все элементы интерфейса используют только этот набор иконок.

Использование отдельных растровых изображений для стандартных элементов интерфейса не допускается.

---

# Architecture

Иконки являются частью подсистемы GUI.

Общая схема использования:

```text
GUI

↓

Theme Manager

↓

Icon Manager

↓

LVGL Font

↓

Display
```

GUI использует логические идентификаторы иконок, а не конкретные графические ресурсы.

---

# Responsibilities

## Icon Manager

Подсистема управления иконками отвечает за:

* регистрацию набора иконок;
* предоставление доступа к пиктограммам;
* поддержку тем оформления;
* централизованное использование иконок во всём интерфейсе.

---

## GUI

GUI использует только логические имена иконок.

Например:

* ICON_HOME;
* ICON_BACK;
* ICON_SETTINGS;
* ICON_USB;
* ICON_WIFI;
* ICON_LOCK;
* ICON_UNLOCK.

GUI не должен знать внутреннюю реализацию набора иконок.

# Theme Support

Иконки должны автоматически использовать цвета активной темы оформления.

При смене темы:

* форма иконок не изменяется;
* изменяются только параметры отображения.

Это обеспечивает единый внешний вид интерфейса.

---

# Resource Efficiency

Использование шрифта иконок позволяет:

* значительно уменьшить объём Flash-памяти;
* исключить хранение большого количества отдельных изображений;
* использовать масштабирование средствами LVGL;
* упростить обновление интерфейса.

---

# Rationale

Использование единой системы иконок обеспечивает:

* единый стиль интерфейса;
* компактное хранение ресурсов;
* высокую производительность отображения;
* удобство сопровождения;
* поддержку различных размеров и масштабирования;
* простую интеграцию с системой тем.

Такой подход полностью соответствует архитектуре GUI проекта.

---

# Consequences

После принятия данного решения:

* все новые экраны используют только зарегистрированные иконки;
* запрещается добавлять отдельные изображения для стандартных элементов интерфейса;
* новые пиктограммы добавляются централизованно через Icon Manager;
* изменение набора иконок не требует изменения экранов GUI.

---

# Alternatives Considered

## Отдельные PNG-изображения

Преимущества:

* простота подготовки графики;
* возможность использования сложных изображений.

Недостатки:

* увеличение размера прошивки;
* отсутствие масштабируемости;
* сложность поддержки нескольких тем;
* большое количество графических ресурсов.

Данный вариант был отклонён.

---

## SVG-иконки

Рассматривалась возможность использования SVG.

Недостатки:

* увеличение вычислительной нагрузки;
* более сложный рендеринг;
* отсутствие преимуществ для небольшого встроенного дисплея.

Данный вариант также был отклонён.

# Summary

Проект **KeyKeeper2** использует централизованную **Icon Font System** для отображения всех стандартных элементов пользовательского интерфейса.

Единая система иконок обеспечивает компактное хранение графических ресурсов, единообразный внешний вид, поддержку тем оформления и упрощает сопровождение графического интерфейса без нарушения компонентной архитектуры проекта.
