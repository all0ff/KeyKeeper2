# ADR-001 — Use ESP-IDF

**Status:** Accepted

**Date:** YYYY-MM-DD

**Version:** 2.0

---

# Context

Проект **KeyKeeper2** разрабатывается для микроконтроллера **ESP32-S3** и представляет собой сложную встроенную систему, включающую графический интерфейс пользователя, защищённое хранилище данных, USB HID, Web UI, Wi-Fi, файловую систему, многозадачность и криптографические механизмы.

Для реализации этих требований необходима современная, поддерживаемая и хорошо документированная программная платформа, обеспечивающая полный доступ к возможностям аппаратного обеспечения.

При выборе основы проекта рассматривались несколько вариантов:

* ESP-IDF;
* Arduino Framework;
* Arduino поверх ESP-IDF;
* собственная программная платформа.

---

# Decision

В качестве единственной программной платформы проекта принято решение использовать **ESP-IDF** (Espressif IoT Development Framework).

Все компоненты проекта разрабатываются исключительно с использованием официального API ESP-IDF.

Использование Arduino Framework или библиотек, требующих Arduino Core, в проекте не допускается.

---

# Rationale

Использование ESP-IDF обеспечивает следующие преимущества:

* официальную поддержку производителя микроконтроллеров Espressif;
* полный доступ ко всем аппаратным возможностям ESP32-S3;
* встроенную поддержку FreeRTOS;
* интеграцию с TinyUSB;
* встроенную поддержку Wi-Fi и Bluetooth;
* развитую систему журналирования;
* современные средства сборки на базе CMake;
* долгосрочную поддержку (LTS);
* высокую стабильность и производительность.

Кроме того, ESP-IDF полностью соответствует архитектурным требованиям проекта и позволяет реализовать компонентную структуру программного обеспечения.

---

# Consequences

После принятия данного решения:

* все новые компоненты должны использовать API ESP-IDF;
* структура проекта строится в соответствии с рекомендациями Espressif;
* сборка выполняется средствами `idf.py` и CMake;
* многозадачность реализуется средствами FreeRTOS, входящей в состав ESP-IDF;
* работа с USB осуществляется через TinyUSB, поставляемую вместе с ESP-IDF;
* использование сторонних фреймворков, изменяющих архитектуру проекта, не допускается.

---

# Alternatives Considered

## Arduino Framework

Преимущества:

* низкий порог входа;
* большое количество готовых библиотек.

Недостатки:

* ограниченный доступ к возможностям ESP32-S3;
* менее гибкая архитектура;
* сложность интеграции с промышленной компонентной структурой;
* зависимость от Arduino Core.

По этим причинам данный вариант был отклонён.

---

## Arduino + ESP-IDF

Преимущества:

* возможность использования библиотек Arduino;
* доступ к части возможностей ESP-IDF.

Недостатки:

* усложнение архитектуры;
* дополнительные зависимости;
* увеличение объёма программного обеспечения;
* более сложное сопровождение проекта.

Данный вариант также был отклонён.

---

## Собственная платформа

Разработка собственной платформы потребовала бы реализации большого количества уже существующих механизмов:

* управления задачами;
* драйверов;
* файловой системы;
* USB;
* сетевого стека;
* средств сборки.

Такой подход признан нецелесообразным.

# Summary

Проект **KeyKeeper2** полностью основан на **ESP-IDF**, которая является единственной официально поддерживаемой платформой разработки.

Это решение обеспечивает максимальную совместимость с аппаратной платформой ESP32-S3, позволяет использовать современные возможности экосистемы Espressif и служит фундаментом для всей архитектуры проекта.
