# LVGL Development Guide

**Project:** KeyKeeper2

**Version:** 2.0

---

# Purpose

Документ определяет правила использования библиотеки **LVGL** в проекте **KeyKeeper2**.

Он описывает:

* организацию графического интерфейса;
* структуру экранов;
* жизненный цикл объектов LVGL;
* взаимодействие GUI с сервисным слоем;
* правила разработки пользовательского интерфейса.

Документ не является руководством по LVGL и не заменяет официальную документацию библиотеки.

---

# Supported Version

Проект использует:

**LVGL 9.x**

Использование других версий допускается только после обновления архитектурной документации.

---

# GUI Architecture

LVGL является графическим движком проекта.

Архитектура пользовательского интерфейса выглядит следующим образом:

```text id="5d4nlf"
Application

↓

GUI

↓

LVGL

↓

Display Driver

↓

BSP

↓

Display Hardware
```

LVGL отвечает только за построение интерфейса.

Бизнес-логика располагается вне GUI.

---

# Responsibilities

LVGL используется только для:

* создания экранов;
* отображения информации;
* обработки пользовательского ввода;
* выполнения анимаций;
* управления виджетами.

LVGL не отвечает за:

* хранение данных;
* безопасность;
* USB;
* работу с файлами;
* сетевое взаимодействие.

---

# Screen Model

Интерфейс состоит из независимых экранов.

Каждый экран отвечает только за собственное отображение.

Типичные экраны:

* Splash Screen;
* Lock Screen;
* Quick Screen;
* Main Menu;
* Vault;
* Settings;
* USB;
* Wi-Fi;
* About.

Каждый экран реализуется как отдельный модуль.

---

# Screen Lifecycle

Каждый экран проходит одинаковые этапы жизненного цикла.

```text id="zljlwm"
Create

↓

Initialize

↓

Show

↓

Update

↓

Hide

↓

Destroy
```

Экран не должен существовать дольше необходимого.

---

# Widget Hierarchy

Все элементы интерфейса строятся как дерево объектов LVGL.

Типичная структура:

```text id="y3mjlwm"
Screen

├── Header

├── Content

│   ├── List

│   ├── Labels

│   ├── Buttons

│   └── Icons

└── Footer
```

Иерархия должна быть простой и легко читаемой.

---

# Event Handling

Обработка пользовательского ввода выполняется через события LVGL.

После получения события экран:

1. анализирует действие пользователя;
2. преобразует его в команду;
3. передаёт команду в EventBus или соответствующий сервис.

GUI не выполняет бизнес-логику самостоятельно.

---

# Navigation

Навигация осуществляется через централизованный Navigation Manager.

Экран не должен самостоятельно переключать другие экраны.

Используются операции:

* Push;
* Pop;
* Replace;
* Back.

Это обеспечивает единое поведение интерфейса.

---

# GUI and Service Layer

Взаимодействие GUI с системой выглядит следующим образом:

```text id="v2cbvw"
User

↓

LVGL

↓

GUI

↓

EventBus

↓

Service Layer
```

GUI не обращается напрямую к:

* StorageService;
* SecurityService;
* USBService;
* WebService.

Все операции выполняются через сервисный слой.

---

# Themes

Проект использует централизованную систему тем.

Theme Manager отвечает за:

* цвета;
* шрифты;
* размеры;
* стили элементов.

Экраны не должны самостоятельно изменять параметры темы.

---

# Icons

Все пиктограммы используются через Icon Manager.

GUI работает только с логическими идентификаторами:

* ICON_HOME;
* ICON_LOCK;
* ICON_USB;
* ICON_WIFI;
* ICON_SETTINGS.

Использование отдельных графических изображений для стандартных элементов интерфейса не допускается.

---

# Fonts

Используются только зарегистрированные шрифты проекта.

Добавление новых шрифтов должно быть согласовано с архитектурой GUI.

---

# Animations

Анимации применяются только для улучшения пользовательского опыта.

Они должны быть:

* короткими;
* плавными;
* ненавязчивыми.

Анимации не должны влиять на производительность системы.

---

# Performance

При разработке GUI рекомендуется:

* минимизировать количество одновременно существующих объектов;
* повторно использовать виджеты при возможности;
* избегать частого удаления и создания объектов;
* обновлять только изменившиеся элементы интерфейса.

---

# Memory Management

Все объекты LVGL создаются и уничтожаются централизованно.

После удаления объекта не допускается хранение указателей на него.

Жизненный цикл объектов должен полностью контролироваться экраном или Navigation Manager.

---

# Thread Safety

LVGL не является потокобезопасной библиотекой.

Все обращения к объектам LVGL выполняются из GUI Task.

Другие задачи должны взаимодействовать с GUI через EventBus или очередь сообщений.

Прямой доступ к объектам LVGL из сторонних задач запрещён.

---

# Display Driver

GUI не взаимодействует с дисплеем напрямую.

Взаимодействие осуществляется через BSP и драйвер отображения.

Это обеспечивает независимость интерфейса от конкретной аппаратной платформы.

---

# Best Practices

При разработке рекомендуется:

* разделять отображение и бизнес-логику;
* создавать независимые экраны;
* использовать повторно стили и виджеты;
* минимизировать глубину дерева объектов;
* соблюдать единый стиль интерфейса;
* использовать только зарегистрированные темы и иконки.

# Summary

Проект **KeyKeeper2** использует **LVGL 9.x** в качестве единственного графического движка пользовательского интерфейса.

LVGL отвечает исключительно за отображение информации и обработку пользовательского ввода. Бизнес-логика полностью вынесена в сервисный слой, а взаимодействие компонентов осуществляется через EventBus. Такой подход обеспечивает модульность, упрощает сопровождение интерфейса и соответствует общей компонентной архитектуре проекта.
