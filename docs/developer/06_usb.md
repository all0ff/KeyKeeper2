# USB Development Guide

**Project:** KeyKeeper2

**Version:** 2.0

---

# Purpose

Документ определяет правила разработки USB-подсистемы проекта **KeyKeeper2**.

Он описывает:

* архитектуру USB;
* USBService;
* взаимодействие с GUI;
* работу с USB HID;
* безопасность;
* обмен событиями;
* обработку подключения устройства.

Документ предназначен для разработчиков, работающих с USB и сервисным слоем проекта.

---

# Architecture Position

USB является отдельным сервисом архитектуры.

Общая схема:

```text id="g7s1fr"
GUI

↓

EventBus

↓

USBService

↓

TinyUSB

↓

ESP-IDF

↓

USB Controller
```

Все операции USB выполняются через USBService.

---

# Design Principles

Подсистема USB построена на следующих принципах:

* единый сервис;
* отсутствие прямого доступа к TinyUSB;
* разделение транспортного уровня и бизнес-логики;
* безопасность по умолчанию;
* взаимодействие через EventBus.

---

# Responsibilities

USBService отвечает за:

* инициализацию USB;
* управление подключением;
* регистрацию HID-интерфейсов;
* передачу HID-отчётов;
* обработку состояния соединения;
* публикацию событий USB.

USBService не отвечает за:

* хранение данных;
* проверку PIN;
* генерацию OTP;
* управление интерфейсом.

---

# Supported Modes

Проект поддерживает режим:

* USB HID Keyboard.

Другие режимы могут быть добавлены в будущем через расширение USBService без изменения архитектуры.

---

# Initialization

Последовательность инициализации:

```text id="h49r2u"
ESP-IDF

↓

TinyUSB

↓

USBService

↓

EventBus
```

После завершения инициализации USBService публикует событие готовности.

---

# Connection Lifecycle

Типичный жизненный цикл USB:

```text id="x8q2cn"
Initialize

↓

Connect

↓

Ready

↓

Transfer

↓

Disconnect
```

Каждое изменение состояния сопровождается публикацией соответствующего события.

---

# HID Reports

USBService формирует HID-отчёты на основе данных, предоставленных сервисами приложения.

Самостоятельная генерация HID-отчётов в GUI запрещена.

---

# Data Flow

Передача данных пользователю:

```text id="hcx5su"
GUI

↓

SecurityService

↓

VaultService

↓

USBService

↓

USB HID
```

GUI инициирует действие, но не взаимодействует с USB напрямую.

---

# EventBus Integration

USBService публикует события:

* USB Connected;
* USB Disconnected;
* USB Ready;
* Transfer Started;
* Transfer Finished;
* Transfer Failed.

Другие компоненты подписываются на события через EventBus.

---

# Security

Перед передачей конфиденциальных данных USBService обязан убедиться, что доступ разрешён.

Проверка выполняется через SecurityService.

USBService не хранит состояние аутентификации самостоятельно.

---

# User Interaction

Типичный сценарий передачи данных:

```text id="u6mjlwm"
User

↓

GUI

↓

Security Check

↓

VaultService

↓

USBService

↓

Host Computer
```

Такое разделение исключает смешение ответственности между компонентами.

---

# Error Handling

USBService должен обрабатывать:

* отсутствие подключения;
* ошибки инициализации;
* ошибки передачи;
* таймауты;
* отключение кабеля во время передачи.

Ошибки публикуются через EventBus и доступны для отображения в GUI.

---

# Thread Safety

Все взаимодействие с USB выполняется через USBService.

Другие компоненты не должны обращаться к TinyUSB напрямую.

При необходимости синхронизация выполняется внутри USBService.

---

# Performance

Рекомендуется:

* избегать длительных блокирующих операций;
* формировать HID-отчёты заранее;
* минимизировать задержку между запросом и передачей;
* использовать очереди сообщений для обмена между задачами.

---

# Testing

Подсистема USB должна тестироваться отдельно.

Необходимо проверять:

* подключение устройства;
* отключение устройства;
* передачу HID-отчётов;
* последовательность событий;
* обработку ошибок;
* взаимодействие с SecurityService.

---

# Best Practices

При разработке рекомендуется:

* использовать только публичный API USBService;
* не обращаться напрямую к TinyUSB;
* выполнять проверки безопасности перед передачей данных;
* использовать EventBus для уведомлений;
* не размещать USB-логику в GUI;
* соблюдать компонентную архитектуру проекта.

# Summary

Подсистема USB проекта **KeyKeeper2** реализована как отдельный сервис **USBService**, обеспечивающий централизованную работу с USB HID.

Все взаимодействие с аппаратным USB выполняется через сервисный слой, а бизнес-логика и проверка безопасности остаются в соответствующих компонентах. Такой подход обеспечивает модульность, упрощает сопровождение и полностью соответствует общей архитектуре проекта.
