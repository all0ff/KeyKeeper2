# Project Goals

KeyKeeper2 представляет собой автономное устройство для безопасного хранения и использования конфиденциальных данных пользователя.

Основные возможности проекта:

* безопасное хранение данных;
* управление учётными записями;
* генерация OTP;
* USB HID;
* Web UI;
* резервное копирование;
* импорт и экспорт данных.

---

# Architectural Principles

Проект построен на следующих принципах:

* Component-Based Architecture;
* Service Layer;
* Event-Driven Architecture;
* Single Responsibility;
* Documentation First;
* Hardware Abstraction.

Каждый компонент отвечает только за собственную область ответственности.

---

# High-Level Architecture

Программное обеспечение разделено на несколько уровней.

```text
Application

↓

GUI

↓

EventBus

↓

Service Layer

↓

Storage / BSP

↓

ESP-IDF

↓

Hardware
```

Ни один уровень не должен нарушать границы другого.

---

# Main Components

Основные компоненты проекта:

* GUI;
* SecurityService;
* VaultService;
* StorageService;
* USBService;
* WebService;
* WiFiService;
* SettingsService;
* EventBus;
* BSP.

Каждый компонент имеет собственную область ответственности.

---

# Service Layer

Service Layer является центральной частью приложения.

Он содержит бизнес-логику проекта и обеспечивает взаимодействие между компонентами.

Сервисы не должны обращаться друг к другу напрямую.

Все взаимодействие выполняется через публичные интерфейсы и EventBus.

---

# Security Model

Все защищённые операции проходят через SecurityService.

Сервис отвечает за:

* проверку PIN;
* пользовательскую сессию;
* автоблокировку;
* контроль доступа.

Другие компоненты не принимают решений о безопасности.

---

# Storage Model

Работа с данными осуществляется через StorageService.

StorageService использует StorageProvider и скрывает детали работы с LittleFS и microSD.

Прямой доступ к файловой системе запрещён.

---

# EventBus

EventBus используется для обмена событиями между компонентами.

Компоненты не должны знать о внутреннем устройстве друг друга.

Используются две операции:

* Publish;
* Subscribe.

Это уменьшает связанность системы и упрощает её развитие.

---

# GUI

GUI отвечает только за пользовательский интерфейс.

Запрещается размещать в GUI:

* бизнес-логику;
* криптографию;
* работу с файлами;
* аппаратно-зависимый код.

GUI взаимодействует с системой исключительно через сервисы и EventBus.

---

# BSP

Board Support Package изолирует аппаратную часть проекта.

BSP отвечает за:

* GPIO;
* дисплей;
* кнопки;
* энкодер;
* подсветку;
* USB;
* SPI;
* SDMMC.

Остальные компоненты используют только публичный API BSP.

# Coding Rules

При разработке необходимо соблюдать следующие правила:

* использовать только публичные интерфейсы компонентов;
* не обращаться напрямую к аппаратному обеспечению;
* не размещать бизнес-логику в GUI;
* использовать EventBus для обмена событиями;
* соблюдать правила, описанные в CODING_STANDARD.md;
* придерживаться принципа Documentation First.
