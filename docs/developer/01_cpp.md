# Modern C++ Guidelines

**Project:** KeyKeeper2

**Version:** 2.0

---

# Purpose

Документ определяет правила использования языка **C++** в проекте **KeyKeeper2**.

Он не является учебником по C++.

Его задача — установить единый стиль разработки, который используется во всех компонентах проекта.

Все разработчики должны придерживаться данных рекомендаций.

---

# Supported Standard

Проект использует стандарт

**C++17**

Использование возможностей более поздних стандартов допускается только после принятия соответствующего архитектурного решения.

---

# General Principles

При разработке необходимо придерживаться следующих принципов:

* простота;
* читаемость;
* предсказуемость;
* безопасность;
* минимальное использование динамической памяти;
* высокая производительность.

Код должен быть понятен без дополнительных комментариев.

---

# Project Philosophy

Проект придерживается следующих правил.

* RAII вместо ручного управления ресурсами.
* Композиция предпочтительнее наследования.
* Явное лучше неявного.
* Константность по умолчанию.
* Минимизация глобального состояния.
* Предпочтение статической типизации.

---

# File Organization

Каждый компонент содержит:

```text id="e72n84"
include/

src/

tests/
```

Заголовочные файлы содержат только объявления.

Исходные файлы содержат реализацию.

---

# Header Files

Рекомендуемый порядок содержимого:

```cpp
#pragma once

#include <...>

namespace kk
{

class Example
{
public:

private:
};

}
```

Использование include guards допускается, но рекомендуется `#pragma once`.

---

# Namespaces

Все компоненты располагаются внутри пространства имён проекта.

Например:

```cpp
namespace kk
{
}
```

Для внутренних подсистем допускаются вложенные пространства имён.

```cpp
namespace kk::storage
{
}
```

---

# Classes

Каждый класс должен иметь одну область ответственности.

Не допускаются классы, объединяющие:

* GUI;
* бизнес-логику;
* работу с оборудованием;
* хранение данных.

Если класс начинает выполнять несколько различных функций, он должен быть разделён.

---

# Constructors

Предпочтительно использовать:

* member initializer list;
* explicit constructors;
* default constructors;
* delete для запрещённых операций.

Например:

```cpp
explicit VaultService();
```

---

# RAII

Все ресурсы должны освобождаться автоматически.

Использование RAII обязательно для:

* файлов;
* памяти;
* мьютексов;
* соединений;
* аппаратных ресурсов.

Ручное освобождение ресурсов должно использоваться только при объективной необходимости.

---

# Memory Management

Предпочтительно использовать автоматическое управление памятью.

Разрешается:

* stack allocation;
* std::unique_ptr;
* std::shared_ptr (только при совместном владении).

Использование `new` и `delete` напрямую запрещено, кроме низкоуровневых компонентов, где это документировано.

---

# Const Correctness

Все объекты должны объявляться как `const`, если они не изменяются.

Методы, не изменяющие состояние объекта, должны быть объявлены как `const`.

---

# References

Предпочтительно использовать ссылки.

Передача крупных объектов по значению запрещена.

Например:

```cpp
void process(const Account& account);
```

---

# Smart Pointers

Предпочтительный порядок использования:

1. std::unique_ptr
2. std::shared_ptr
3. std::weak_ptr

Использование сырых указателей допускается только как невладеющих ссылок.

---

# Error Handling

Для обработки ошибок используются:

* std::optional;
* std::expected (при появлении поддержки);
* enum Result;
* ErrorCode.

Использование исключений в прикладном коде проекта запрещено.

---

# STL Usage

Разрешается использовать:

* vector;
* array;
* string;
* span;
* optional;
* variant;
* map;
* unordered_map;
* algorithm.

Следует избегать контейнеров с избыточным потреблением памяти, если это не оправдано требованиями функциональности.

---

# Dynamic Allocation

Динамическое выделение памяти допускается только при необходимости.

Предпочтительно:

* размещение объектов на стеке;
* статические объекты;
* предварительное резервирование памяти.

---

# Templates

Шаблоны следует использовать только при наличии явных преимуществ.

Избыточное применение шаблонного программирования не рекомендуется.

---

# Inheritance

Наследование используется только тогда, когда действительно существует отношение "является".

Во всех остальных случаях следует использовать композицию.

---

# Interfaces

Абстрактные интерфейсы применяются для:

* сервисов;
* драйверов;
* тестирования;
* аппаратной абстракции.

Интерфейсы должны содержать только публичный API.

---

# Thread Safety

Компоненты должны быть максимально независимыми.

Совместный доступ к данным должен минимизироваться.

Синхронизация выполняется средствами FreeRTOS или стандартных примитивов, используемых в проекте.

---

# Logging

Для журналирования используется единый Logger.

Использование printf в прикладном коде запрещено.

---

# Assertions

Для проверки внутренних условий используются:

* assert;
* ESP_ASSERT;
* специальные диагностические проверки.

Проверки пользовательского ввода не должны использовать assert.

# Summary

Проект **KeyKeeper2** использует современный стиль программирования на **C++17**, основанный на принципах RAII, композиции, строгой типизации и безопасного управления ресурсами.

Основной целью данных рекомендаций является создание читаемого, сопровождаемого и предсказуемого кода, полностью соответствующего компонентной архитектуре проекта и требованиям встроенных систем.
