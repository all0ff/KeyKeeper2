# Wi-Fi Development Guide

**Project:** KeyKeeper2

**Version:** 2.0

---

# Purpose

Документ определяет правила разработки сетевой подсистемы проекта **KeyKeeper2**.

Он описывает:

* архитектуру Wi-Fi;
* WiFiService;
* режимы работы;
* взаимодействие с WebService;
* безопасность;
* обработку сетевых событий;
* интеграцию с EventBus.

Документ предназначен для разработчиков, работающих с сетевыми функциями проекта.

---

# Architecture Position

Подсистема Wi-Fi является отдельным сервисом архитектуры.

Общая схема:

```text id="grzvna"
GUI

↓

EventBus

↓

WiFiService

↓

ESP-IDF Wi-Fi

↓

ESP32-S3
```

Все операции работы с сетью выполняются через WiFiService.

---

# Design Principles

Подсистема построена на следующих принципах:

* единая точка управления сетью;
* отсутствие прямого использования ESP-IDF Wi-Fi API;
* разделение сетевого транспорта и бизнес-логики;
* централизованная обработка состояния подключения;
* взаимодействие компонентов через EventBus.

---

# Responsibilities

WiFiService отвечает за:

* инициализацию Wi-Fi;
* управление режимами работы;
* подключение к сети;
* запуск точки доступа;
* контроль состояния соединения;
* публикацию сетевых событий.

WiFiService не отвечает за:

* HTTP;
* Web UI;
* безопасность пользователей;
* хранение настроек;
* работу пользовательского интерфейса.

---

# Supported Modes

Поддерживаются следующие режимы:

* Station Mode (STA);
* Access Point (AP).

Переключение между режимами осуществляется только через публичный API WiFiService.

---

# Initialization

Последовательность запуска:

```text id="8r4jyn"
ESP-IDF

↓

WiFi Driver

↓

WiFiService

↓

EventBus
```

После успешной инициализации публикуется событие готовности сети.

---

# Connection Lifecycle

Типичный жизненный цикл подключения:

```text id="jxytzy"
Initialize

↓

Start

↓

Connect

↓

Connected

↓

Disconnect

↓

Reconnect
```

Каждое изменение состояния сопровождается публикацией события.

---

# Network Configuration

Настройки сети включают:

* режим работы;
* SSID;
* пароль;
* параметры безопасности;
* IP-конфигурацию (при необходимости).

Конфигурация хранится через SettingsService.

---

# WebService Integration

WiFiService предоставляет сетевое соединение для WebService.

Типичный поток:

```text id="r7xvmo"
GUI

↓

WiFiService

↓

WebService

↓

HTTP Server
```

WebService не управляет подключением Wi-Fi самостоятельно.

---

# EventBus Integration

WiFiService публикует события:

* Wi-Fi Started;
* Wi-Fi Stopped;
* Connected;
* Disconnected;
* Connection Failed;
* Access Point Started;
* Access Point Stopped.

Компоненты получают информацию только через EventBus.

---

# Security

Подключение к сети должно соответствовать требованиям безопасности проекта.

Рекомендуется:

* использовать WPA2/WPA3 (в зависимости от поддержки платформы);
* не хранить пароли в открытом виде;
* выполнять проверку прав доступа перед изменением сетевой конфигурации.

Контроль доступа выполняется SecurityService.

---

# GUI Interaction

GUI не взаимодействует с ESP-IDF Wi-Fi API напрямую.

Типичный сценарий:

```text id="mjlwm3"
User

↓

GUI

↓

WiFiService

↓

ESP-IDF
```

GUI только отображает состояние сети и инициирует команды.

---

# Error Handling

WiFiService должен обрабатывать:

* ошибки инициализации;
* невозможность подключения;
* потерю соединения;
* ошибки аутентификации;
* повторные попытки подключения.

Все ошибки публикуются через EventBus и могут отображаться в GUI.

---

# Thread Safety

Все операции с Wi-Fi выполняются внутри WiFiService.

Другие компоненты не должны использовать драйвер ESP-IDF напрямую.

При необходимости синхронизация выполняется внутри сервиса.

---

# Performance

Рекомендуется:

* не выполнять длительные операции в обработчиках событий;
* ограничивать количество повторных подключений;
* минимизировать сетевую активность в фоновом режиме;
* использовать событийную модель вместо постоянного опроса состояния.

---

# Testing

Подсистема Wi-Fi должна тестироваться отдельно.

Необходимо проверять:

* запуск станции;
* запуск точки доступа;
* успешное подключение;
* потерю соединения;
* восстановление подключения;
* обработку ошибок;
* взаимодействие с WebService.

---

# Best Practices

При разработке рекомендуется:

* использовать только публичный API WiFiService;
* не обращаться напрямую к ESP-IDF Wi-Fi API;
* публиковать изменения состояния через EventBus;
* хранить конфигурацию через SettingsService;
* разделять сетевую инфраструктуру и прикладную логику;
* соблюдать компонентную архитектуру проекта.

# Summary

Подсистема **Wi-Fi** проекта **KeyKeeper2** реализована как отдельный сервис **WiFiService**, обеспечивающий централизованное управление сетевыми подключениями.

Все операции с сетью выполняются через сервисный слой, а взаимодействие с другими компонентами осуществляется посредством EventBus. Такой подход обеспечивает модульность, упрощает сопровождение проекта и соответствует общей компонентной архитектуре системы.
