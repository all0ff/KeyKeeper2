# kkproto -- encrypted link between the vault and a radio dongle

Portable protocol library (C++17, no exceptions, no heap, no platform dependencies except one
small crypto interface). The same source is built into the vault firmware (ESP-IDF) and into
the dongle firmware (nRF52840 or ESP32-S3). **Disabled by default** -- see "Enabling" below.

| Module | What it does |
|---|---|
| `crypto_port.hpp` | The ONLY per-platform part: X25519, SHA-256, HMAC-SHA256, ChaCha20-Poly1305, RNG, and `selftest()` |
| `noise.hpp/.cpp` | Noise Protocol Framework: `Noise_XX_25519_ChaChaPoly_SHA256` (pairing) and `Noise_IK_...` (sessions), `Transport` |
| `frames.hpp/.cpp` | 2-byte length framing and a stream `Reader` that reassembles frames from arbitrary BLE chunks |
| `messages.hpp/.cpp` | Application messages (`HELLO`, `TYPE`, `RESULT`, ...), the 6-byte typing event, the dongle's acceptance rules |
| `pairing.hpp/.cpp` | Noise prologue and the 6-digit verification code (SAS) derived from the handshake hash |

Ports (exactly one is linked): `platform/psa` (ESP-IDF / PSA Crypto), `platform/sodium`
(libsodium: nRF52840 / Arduino / host), `platform/openssl` (host reference only).

## What was verified (on a PC)

* The 6 **official Noise test vectors** for our two protocols (from the cacophony, snow and
  noise-c vector sets) pass byte for byte on **all three ports**: every handshake and transport
  ciphertext and the final handshake hash.
* A deterministic pairing + session scenario gives a **byte-identical transcript** on libsodium,
  OpenSSL and mbedTLS/PSA.
* Message sizes match the specification (XX 32/96/64 bytes, IK 96/48, empty payloads).
* Flipping **any single bit of any handshake message** (2688 runs) is always detected.
* Replay, reordering, a dropped message, truncation, a reflected message, a wrong prologue, a wrong
  peer key, nonce exhaustion, and low-order X25519 points are all rejected.
* Codecs are fuzzed (message, frame, noise inputs) under ASan/UBSan: no crash; whatever a decoder
  accepts re-encodes to identical bytes; the stream `Reader` matches an independent reference parser.
* The verification code has independently computed known answers, is uniform (chi-square) and a
  man in the middle gets matching codes ~1e-6 per attempt (0 of 1000 observed).
* The test suite itself was mutation-checked: 18 planted bugs, all caught
  (`test_host/mutation_check.py`). Two defences (core zero-DH check, `selftest()`) are tested against
  deliberately broken ports (`test_host/broken_ports/`).

Run: `test_host/run_host_tests.sh` (see the header of that script; `MBEDTLS_DIR=...` adds the PSA port).

## What was NOT verified

* **A build with the real ESP-IDF toolchain** (the PSA port was compiled and tested against mbedTLS 3.6.2
  on a PC; ESP-IDF 6.x bundles a newer mbedTLS, same PSA API). Check on the first build.
* **Whether your mbedTLS configuration has X25519 and ChaCha20-Poly1305 enabled.** `kk::crypto::selftest()`
  tells you at run time; call it once at boot of anything using the link.
* **Speed and RAM on the device.** On a PC the PSA path is ~14x slower than libsodium (each PSA call
  imports a key); a full IK handshake is 8 X25519 operations. Measure on the board.
* Side channels, and an independent security review. This is a careful implementation of a standard
  protocol, not an audited one. Constant-time behaviour and key wiping rely on the platform library
  and on best-effort zeroing here.

## Memory (platform independent)

`HandshakeState` 424 B, `Transport` 96 B, `frame::Reader` 552 B, `msg::Event` 6 B. No heap.

## Enabling in the vault firmware

`idf.py menuconfig` -> "KeyKeeper2 secure radio link (kkproto)" -> enable. Until something calls the
library it only costs flash for the linked-in functions (none, if nothing references them).

## Test vectors

`test_host/vectors/noise_vectors.txt` is generated by `tools/convert_vectors.py` from the three public
sources named in its header (their SHA-256 are recorded there).
